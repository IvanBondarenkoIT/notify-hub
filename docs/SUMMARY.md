# Сводка для руководителя

Коротко: что задумали, что сделали, зачем это бизнесу. Без технических деталей.

## Зачем

Раньше каждое приложение (календарь и следующие) само писало в Telegram. Это неудобно:

- несколько ботов и разные правила доставки;
- сложно добавить новый вид оповещений (склад, задачи, безопасность);
- риск двойных сообщений и путаницы «кто кому пишет».

**Задумали одно место для всех уведомлений команды.** Системы не стучатся в Telegram сами: говорят хабу «случилось вот это» — хаб доставляет людям.

## Что разработано

Рабочий сервис **Notify Hub** (хаб уведомлений DimKava / Granit):

- принимает событие от любой нашей системы;
- не шлёт одно и то же дважды;
- доставляет сообщение в привычный Telegram.

Три «корзины» сообщений — три бота Telegram (общие / служебные / личные). Кнопки «подтвердил» — следующий этап.

## Что уже сделано (сейчас)

- Хаб написан, лежит в GitHub, крутится на сервере круглосуточно.
- Три бота заведены и проверены (18.09.2026): **DimKava Public / Private / Personal Alerts** — тестовые сообщения дошли.
- Для разработчиков и ИИ-агентов есть инструкция: новый проект шлёт одно HTTP-событие, без своего бота.

Календарь событий **пока** шлёт в старый бот. Хаб готов его принять; перевод — следующий шаг, без сюрприза для сотрудников в чате.

## В чём выгода

| Было | Стало / станет |
|------|----------------|
| Каждый сервис = свой бот и своя логика | Один хаб, один привычный канал |
| Новое оповещение = снова писать «телеграм-код» | Новое оповещение = одно событие в хаб |
| Сложно контролировать «ушло / не ушло» | Повтор безопасен, доставка на сервере |
| Склад, задачи, алерты — каждый сам по себе | Та же труба, разные типы сообщений |

**Итог:** инфраструктура уведомлений больше не привязана к одному календарю. Команда может подключать следующие системы быстрее и без второго бота в чате.

## Что ещё не делали (намеренно)

- Календарь не переведён на хаб до конца — чтобы не дублировать сообщения.
- Кнопки «я видел / подтверждаю» и эскалация руководителю — запланированы, в этой версии только заготовка.
- Склад и контроль исполнения — после стабильного пилота с календарём.
